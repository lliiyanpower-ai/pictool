# 智能裁剪功能需求

## 1. 背景

当前图片裁剪主要依赖用户手动选择尺寸或比例，再拖动裁剪框完成构图。

在网站内容维护场景中，用户经常需要处理新闻人物照、会议照片、活动合影、团队照片、横幅大图和栏目封面图。选择目标尺寸后，如果裁剪框默认居中，容易切掉人物头部、主体人物或画面重点，用户需要反复手动调整。

智能裁剪的目标是：在用户选择尺寸或比例后，自动给出一个更合理的初始裁剪位置，减少用户调整成本，同时保留手动控制权。

## 2. 本期范围

本期只包含两类能力：

1. 视觉重心智能裁剪
2. 人脸/人物优先裁剪

本期不包含：

- 通用主体识别
- 云端 AI 裁剪
- 批量智能裁剪
- 网站扫描
- 抠图、扩图、补图
- 自动生成图片内容
- 账号同步或云端保存用户配置

## 3. 产品目标

1. 让裁剪框在默认状态下更接近画面重点，不只是机械居中。
2. 对有人物的图片，尽量优先保留人脸、头部和主要人物区域。
3. 对没有明显人物的图片，使用视觉重心算法寻找更合理的裁剪区域。
4. 在识别失败、模型不可用或浏览器能力不足时，平滑回退到普通裁剪。
5. 保持图片本地处理，不上传用户图片。
6. 保持用户可控，智能裁剪只提供建议，不替代手动调整。

## 4. 适用页面

最终应覆盖：

- 独立图片裁剪页：`crop.html`、`crop.js`
- 工作台裁剪模块：`workspace.html`、`workspace.js`

如果分阶段开发，建议先实现独立裁剪页，验证稳定后再同步工作台。

工作台同步时必须保持现有紧凑编辑器布局，不应把长说明或复杂面板塞进工作台。

## 5. 用户故事

### 5.1 新闻人物图

作为网站编辑，我上传一张人物新闻图，选择新闻封面尺寸后，希望裁剪框自动避开切头、切脸，让人物更完整地出现在画面中。

### 5.2 活动合影

作为活动运营人员，我上传一张多人合影，选择活动封面尺寸后，希望裁剪框尽量覆盖主要人物。如果比例无法容纳所有人，工具应提示可能无法完整保留所有人物。

### 5.3 风景或建筑图

作为网站维护者，我上传一张没有明显人物的建筑或环境图，选择横幅尺寸后，希望裁剪框优先保留画面中信息更丰富、更像重点的区域。

### 5.4 用户手动修正

作为用户，我希望智能裁剪只是帮我先放好裁剪框。如果结果不满意，我可以继续手动拖动和调整，系统不应反复把裁剪框改回去。

## 6. 核心交互

### 6.1 智能构图开关

在裁剪设置区域增加开关：

```text
智能构图
```

说明文案建议：

```text
自动调整裁剪框位置，优先保留人物或画面重点。
```

默认建议：

- 默认开启。
- 用户关闭后，在当前浏览器中记住该选择。
- 配置只保存在本地浏览器中。

### 6.2 重新智能构图

增加轻量按钮：

```text
重新智能构图
```

使用场景：

- 用户手动调整过裁剪框后，想重新使用系统建议。
- 用户更换图片、尺寸或比例后，想主动重新计算。
- 智能构图失败后，用户希望重试。

按钮不应影响用户选择的目标尺寸或比例，只重新计算裁剪框位置。

### 6.3 状态提示

自动调整后给出短状态提示，不使用强打扰弹窗。

推荐文案：

```text
已根据画面重点调整裁剪位置
```

```text
已优先保留人物区域
```

```text
未检测到明显人物，已使用智能构图
```

```text
当前比例较窄，可能无法完整保留所有人物
```

```text
智能构图失败，已使用居中裁剪
```

工作台中可使用更短文案，例如：

```text
已智能构图
```

```text
已优先保留人物
```

## 7. 自动触发规则

开启智能构图后，在以下场景自动触发：

- 用户上传图片后
- 用户选择尺寸预设后
- 用户选择裁剪比例后
- 用户修改目标宽高后
- 用户点击“重新智能构图”后

以下场景不应自动触发：

- 用户正在拖动裁剪框
- 用户正在缩放裁剪框
- 用户已经手动调整过裁剪框，且没有再次点击“重新智能构图”
- 仅因预览刷新、预计大小更新或 UI 重绘导致的状态变化

### 手动接管规则

用户拖动或缩放裁剪框后，系统应认为用户已经接管裁剪结果。

接管后，智能裁剪不应自动抢回控制权。只有以下动作可以重新触发：

- 用户点击“重新智能构图”
- 用户重新上传图片
- 用户明确选择新的尺寸或比例

## 8. 策略优先级

开启智能构图后，裁剪策略按以下优先级执行：

1. 人脸检测成功：优先保留人脸和头部区域。
2. 人物检测成功：优先保留人物身体主体区域。
3. 未检测到人脸或人物：使用视觉重心智能裁剪。
4. 视觉重心计算失败：回退到普通居中裁剪。

简化表达：

```text
人脸优先 > 人物优先 > 视觉重心 > 居中裁剪
```

## 9. 视觉重心智能裁剪

### 9.1 功能说明

视觉重心智能裁剪不识别具体物体，只判断画面中哪里更像视觉重点。

适合图片类型：

- 风景图
- 建筑图
- 环境图
- 活动现场图
- 科研场景图
- 没有明显人物的新闻配图

### 9.2 技术要点

建议流程：

1. 使用 `canvas` 读取图片像素。
2. 对大图进行降采样，避免计算过慢。
3. 分析边缘、亮度变化、对比度、饱和度等信息。
4. 生成简化的视觉显著性分布。
5. 根据当前目标比例生成候选裁剪框。
6. 对候选框打分，选择分数最高的位置。
7. 将结果映射回原图坐标。
8. 保证裁剪框不超出原图边界。

可选方案：

- 使用成熟前端库，例如 `smartcrop.js`。
- 实现轻量自研算法，优先保证速度和可维护性。

产品建议：

第一版优先选择成熟、轻量、可本地运行的方案，避免把主要成本耗在自研算法细节上。

### 9.3 降级规则

以下情况应回退到居中裁剪：

- 图片读取失败
- 视觉评分计算失败
- 候选裁剪框结果非法
- 浏览器性能不足导致计算中断

回退时提示：

```text
智能构图失败，已使用居中裁剪
```

## 10. 人脸/人物优先裁剪

### 10.1 功能说明

当图片中检测到人脸或人物时，系统应自动调整裁剪框位置，尽量保留人物完整，尤其避免切掉脸部和头部。

适合图片类型：

- 新闻人物照
- 活动照片
- 会议照片
- 团队合影
- 采访照片
- 头像或个人照片

### 10.2 技术要点

可选实现方向：

1. 人脸检测
   - 检测脸部位置。
   - 根据人脸框推断头部安全区域。
   - 优先避免切头顶、切脸和贴脸裁剪。

2. 人物检测
   - 检测完整人体或半身区域。
   - 适合活动照、会议照、全身照和多人合影。

3. 组合策略
   - 如果同时检测到人脸和人物，优先用人脸确定关键区域，再结合人物框扩大裁剪范围。
   - 如果只检测到人脸，保住脸部和头部，并保留适当上下文。
   - 如果只检测到人物，保住人物主体区域。

可考虑技术方案：

- `MediaPipe`
- `TensorFlow.js`
- `face-api.js`
- 浏览器可运行的人脸或人体检测模型

要求：

- 在浏览器本地运行。
- 不上传用户图片。
- 模型体积不能过大。
- 移动端性能要可接受。
- 模型加载失败时，不影响普通裁剪。

### 10.3 人脸安全区

裁剪框不应紧贴检测到的人脸边缘。

建议策略：

- 人脸上方保留额外空间，避免切头顶。
- 左右保留适当空间，避免贴脸裁剪。
- 下方保留一定区域，避免只剩脸部没有身体或背景。
- 单人头像场景可以更聚焦；新闻和活动图应保留更多环境上下文。

### 10.4 多人场景

如果检测到多个人：

1. 优先尝试覆盖所有主要人物。
2. 如果目标比例无法覆盖所有人物，优先覆盖最大、最清晰、最靠近画面中心的人物。
3. 不应为了覆盖边缘小人物，导致主要人物被切掉。
4. 如果横向合影被裁成竖图，应提示用户比例较窄。

提示文案：

```text
当前比例较窄，可能无法完整保留所有人物
```

## 11. 裁剪框规则

智能裁剪只调整裁剪框位置，不改变用户选择的尺寸或比例。

自动生成的裁剪框必须满足：

- 不超出图片边界。
- 比例符合当前目标比例。
- 与当前裁剪模式兼容。
- 不擅自改变目标宽度和高度。
- 不破坏现有“应用”后预览同步逻辑。

示例：

如果用户选择 `900 x 383`，智能裁剪只能调整裁剪框在原图中的位置，不能自动改成其他比例。

## 12. 设置保存

建议保存到当前浏览器：

- 智能构图开关状态
- 最近一次使用的智能构图策略，可选

不保存：

- 用户图片
- 人脸数据
- 人物检测框
- 检测截图
- 图片文件名

提示口径：

```text
智能构图设置保存在当前浏览器中，清理缓存后可能丢失。
```

## 13. 隐私边界

本期必须满足：

- 图片不上传服务器。
- 人脸/人物识别在浏览器本地完成。
- 不保存人脸数据。
- 不保存人物检测结果到远端。
- 不采集图片内容。
- 不采集文件名。
- 不采集标题正文。
- 不采集精确图片尺寸。

如果模型从 CDN 或静态资源加载，应明确这是加载模型文件，不是上传用户图片。

如果未来改为云端 AI 识别，必须另行设计产品提示、隐私说明和用户确认流程。本需求不包含云端 AI。

推荐提示：

```text
智能构图在当前浏览器中完成，图片不会上传。
```

## 14. 统计埋点边界

本需求不要求第一阶段必须完成埋点开发，但预留统计边界。

- 人脸坐标

## 15. 异常和降级

### 15.1 模型加载失败

如果人脸或人物检测模型加载失败：

- 不影响图片上传。
- 不影响普通裁剪。
- 不影响下载。
- 自动降级到视觉重心智能裁剪。
- 如果视觉重心也不可用，降级到居中裁剪。

提示：

```text
人物识别暂不可用，已使用智能构图
```

### 15.2 未检测到人物

如果未检测到人脸或人物：

- 使用视觉重心智能裁剪。
- 给出轻量提示。

提示：

```text
未检测到明显人物，已使用智能构图
```

### 15.3 图片过大

如果图片过大：

- 使用缩略图进行识别和分析。
- 将识别结果映射回原图坐标。
- 不应导致页面卡死。
- 必要时显示短暂计算状态。

### 15.4 目标比例过窄

如果目标比例无法完整保留所有人物：

- 尽量保留主要人物。
- 给出提示。

提示：

```text
当前比例较窄，可能无法完整保留所有人物
```

### 15.5 浏览器能力不足

如果浏览器不支持所需能力：

- 保留普通裁剪。
- 能做视觉重心则继续做视觉重心。
- 不能做人物检测时，不阻断用户操作。
- 不阻断下载。

## 16. 阶段拆分

### 阶段 A：需求文档

目标：

- 固化智能裁剪功能边界。
- 明确不做通用主体识别、云端 AI、批量智能裁剪和网站扫描。
- 明确隐私边界和验收标准。

产出：

- `docs/features/smart-crop.md`

### 阶段 B：独立裁剪页视觉重心

目标：

- 在独立裁剪页实现智能构图开关。
- 实现视觉重心智能裁剪。
- 添加“重新智能构图”按钮。
- 添加状态提示。
- 保存开关状态到本地浏览器。
- 保证用户手动调整后不会被系统自动抢回。

### 阶段 C：独立裁剪页人脸/人物优先

目标：

- 接入本地人脸或人物检测能力。
- 检测成功时优先保留人物区域。
- 未检测到人物时回退到视觉重心。
- 模型加载失败时不影响普通裁剪。
- 完成多人和窄比例提示。

### 阶段 D：工作台同步

目标：

- 在工作台裁剪模块同步智能构图开关。
- 同步“重新构图”入口。
- 同步裁剪框自动调整策略。
- 保持工作台紧凑布局。
- 不破坏裁剪、滤镜、标题、导出切换。

### 阶段 E：埋点与发布检查

目标：

- 如需要，补充智能裁剪相关埋点。
- 统一走 `analytics.js`。
- 不采集隐私敏感字段。
- 按 `RELEASE_CHECKLIST.md` 完成发布前检查。

## 17. 验收标准

### 17.1 基础验收

- 用户上传图片后，开启智能构图时裁剪框会自动移动到建议位置。
- 用户选择不同尺寸或比例后，智能构图会重新计算位置。
- 用户关闭智能构图后，使用普通裁剪逻辑。
- 用户可以手动拖动和调整裁剪框。
- 用户手动调整后，系统不会反复自动改回。
- 点击“重新智能构图”后，会重新推荐裁剪位置。
- 智能裁剪不改变用户选择的尺寸或比例。

### 17.2 视觉重心验收

- 没有人物的图片中，裁剪框不只是机械居中。
- 风景、建筑、活动现场等图片能尽量保留视觉重点。
- 算法失败时回退到居中裁剪。
- 大图不会明显卡顿。
- 裁剪框不会超出图片边界。

### 17.3 人脸/人物验收

- 单人照片中，裁剪框优先保留脸部和头部。
- 半身或全身人物照片中，裁剪框尽量保留人物主体。
- 多人照片中，裁剪框尽量覆盖主要人物。
- 目标比例过窄时，有合理提示。
- 未检测到人物时，回退到视觉重心智能裁剪。
- 模型加载失败时，不影响普通裁剪和下载。

### 17.4 工作台验收

- 工作台裁剪模块支持智能构图。
- 工作台裁剪策略与独立裁剪页一致。
- 工作台布局不被长文案撑乱。
- 工作台裁剪、滤镜、标题、导出切换正常。

### 17.5 隐私验收

- 图片不上传服务器。
- 不保存人脸数据。
- 不保存人物检测结果到远端。
- 不上报人脸或人物坐标。
- 不上报图片内容、文件名、标题正文或精确尺寸。

## 18. 产品边界

本版本追求的是“明显比默认居中更聪明”，不是专业级 AI 构图。

不要承诺：

- 100% 保证所有人物完整
- 识别所有主体
- 自动理解图片语义
- 自动生成缺失画面
- 云端 AI 精修效果

推荐对外表达：

```text
智能构图会尽量保留人物或画面重点，裁剪结果仍可手动调整。
```

## 19. 后续对话拆分建议

为了降低开发风险，建议后续按以下对话拆分执行：

1. 独立裁剪页视觉重心智能裁剪。
2. 独立裁剪页人脸/人物优先裁剪。
3. 工作台裁剪模块同步。
4. 埋点与发布检查。

每个对话只处理一个目标，避免同时改算法、UI、工作台和统计。
